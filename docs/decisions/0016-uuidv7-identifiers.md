# ADR 0016 — UUIDv7 identifiers

- Status: Proposed
- Date: 2026-10-22
- Supersedes: none
- Superseded by: none

## Context

Identifiers appear in URLs, logs, and cursor pagination. Random UUIDv4 IDs sort poorly and make index locality worse. Sequential integers leak volume and are awkward for distributed generation later.

## Decision

Use **UUIDv7** for application-generated IDs.

- Generated through `IIdGenerator` using `Guid.CreateVersion7()`.
- Stored as PostgreSQL `uuid`.
- Serialized as lowercase canonical strings.
- Used for projects, deployments, releases, domains, audit, and other aggregate IDs.
- ASP.NET Core Identity user IDs may remain UUIDs generated by Identity, but new Marsa-owned IDs use v7.
- Cursor pagination can use `(created_at, id)` with the time-ordered component.

## Consequences

### Positive

- Roughly time-ordered, better index locality than v4.
- No central sequence or database round trip.
- Works across future processes.
- Safe to expose in URLs.

### Negative

- The timestamp component can reveal creation time; acceptable for this product.
- Not a substitute for a sortable integer in every query.
- Tooling must not assume v4 layout.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| UUIDv4 | Poor index locality; random ordering |
| bigint identity | Leaks volume; harder for future distributed generation |
| ULID | Similar benefits, but UUIDv7 is standardized and built into .NET |
| Composite natural keys | Fragile and hard to change |
